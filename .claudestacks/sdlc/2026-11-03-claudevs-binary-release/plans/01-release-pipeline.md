# Release pipeline Implementation Plan

**Goal:** Publish a `claudevs` archive only after it passes on its own platform.

**Architecture:** dist generates the release workflow from `dist-workspace.toml`. A hand-written reusable
workflow, called through dist's `global-artifacts-jobs` hook, runs each archive on its own platform before
`host` may publish it.

**Tech Stack:** dist 0.33.1, GitHub Actions, POSIX shell inside workflow steps, Cargo manifests.

**Content authority:** `spec.md` sections 2 and 3.

---

## Files that change

```
.github/workflows/claudevs-cli-smoke.yml    — create: hand-written smoke workflow
dist-workspace.toml                         — create: dist configuration
.github/workflows/claudevs-cli-release.yml  — create: generated by dist generate, never hand-edited
Cargo.toml                                  — modify: add [profile.dist]
crates/airsclaude/Cargo.toml                — modify: add [package.metadata.dist] with dist = false
```

## Order of work

### Task 1 — Write the smoke workflow

**Files:**
- Create `.github/workflows/claudevs-cli-smoke.yml` — the workflow in spec section 3.

**Change:** Add the `workflow_call` workflow from `buildl/.github/workflows/buildl-cli-smoke.yml`, keeping its
input, plan-derived matrix (`:45-71`), checksum check (`:104-111`), tar-only unpack (`:121-124`) and Alpine
wrapper (`:131-136`), with the binary's path in `CLAUDEVS` and `claudevs` as the name searched for inside the
archive. The runner table holds the six rows of `buildl-cli-smoke.yml:46-51`, with `aarch64-apple-darwin` on
`macos-15`. The header comment says why that row differs from `airsl` and `buildl`, citing runner-images issue
13518. The steps are those of spec section 3, in its order: Version, Doctor, Wiring fixtures, Test-stage
fixtures. Test-stage fixtures carries a condition that skips it when `matrix.alpine` is true, and its comment
says these fixtures need `git`, which the Alpine container lacks. Each fixture asserts the exit code and lines
in the spec section 3 table. Doctor accepts exit 0 or 1 and prints the manifest line the spec names; exit 2
fails.

**Proof:** The coder copies each step's run block into a temp script and runs it with `CLAUDEVS` set to
`target/debug/claudevs` from `cargo build -p claudevs-cli`, and `VERSION` set to the `version` in
`crates/claudevs-cli/Cargo.toml`. Each is seen failing first with `CLAUDEVS` set to a temp stand-in script that prints
nothing and exits 0, then passing with the real binary. These checks leave no committed artifact; the first pull
request's Release check is the lasting run.
- `smoke_version_step` — fails on the stand-in; passes on the real binary, which prints `claudevs $VERSION`.
- `smoke_doctor_step` — fails on the stand-in, which has no manifest line; passes on the real binary.
- `smoke_wiring_step` — fails on the stand-in; passes on the real binary for the four wiring rows.
- `smoke_test_stage_step` — fails on the stand-in; passes on the real binary for the four test rows.

**Done when:** those four checks pass and `cargo make dod` is green. Commit
`ci(repo): add the claudevs archive smoke workflow`.

### Task 2 — Configure dist and generate the release workflow

**Files:**
- Create `dist-workspace.toml` — exactly the settings in spec section 2, with the comments
  `buildl/dist-workspace.toml:1-36` carries adapted to `claudevs-cli`, and a comment on
  `[dist.github-custom-runners]` giving the retirement as the reason.
- Modify `Cargo.toml` — add `[profile.dist]` as spec section 2 shows it, with `dist`'s heading comment.
- Modify `crates/airsclaude/Cargo.toml` — add `[package.metadata.dist]` with `dist = false`, with a comment saying
  the crate's only binary is a test helper.
- Create `.github/workflows/claudevs-cli-release.yml` — output of `dist generate`.

**Change:** dist plans a single release, `claudevs-cli`, on six targets. No version number changes.

**Proof:**
- `plan_lists_only_claudevs` — seen failing before the `dist = false` line, when `dist plan` lists
  `airsclaude-agent-testchild`; after it, `dist plan` lists `claudevs-cli` alone, with `[bin] claudevs` six times.
- `plan_uses_macos_15` — `dist plan --output-format=json` lists `macos-15` and no `macos-14`.
- `generated_workflow_is_current` — copy the generated file to a temp path, run `dist generate` again, then `cmp` the
  two. Seen failing first by temporarily changing `tag-namespace` before the second run, which `cmp` must report,
  then restoring it and generating again. `cmp` is used because `git diff` reports nothing on a file still untracked.
- `generated_workflow_calls_smoke` — the generated file calls `./.github/workflows/claudevs-cli-smoke.yml`, and
  `host` lists it under `needs`.

**Done when:** those four checks pass and `cargo make dod` is green. Commit
`feat(workspace): configure dist to release the claudevs binary`.

## Risks

- `macos-15` departs from the sibling repositories' runner, so a later copy of their files can reintroduce
  `macos-14`. The comments in both files name the reason.
- Riskiest step: Task 2's `cargo make dod`. `[profile.dist]` and the metadata key are the only manifest changes.
- The smoke workflow runs for real only on a pull request. Spec sections 10 and 11 cover that check, which comes
  after this plan.
- A YAML error in either workflow first shows on the pull request. No workflow parser was confirmed on this machine,
  and the spec requires none.

## Proof

- `dist plan` lists `claudevs-cli` alone on six targets.
- `generated_workflow_is_current` passes after the last edit to `dist-workspace.toml`.
- `cargo make dod` is green.
